Documentation

Tout ce qu'il faut savoir pour lancer le projet en local et ajouter un nouveau jeu dans les règles de l'art.

Structure du repo

Les pages du site (accueil, à propos, documentation...) partagent un même en-tête et un même design système, définis une seule fois dans assets/. Chaque jeu vit dans le dossier de son développeur, sous games/ : un dossier par développeur, un fichier HTML autonome par jeu. La liste des jeux affichée sur le site est générée automatiquement à partir de ces fichiers, elle n'est jamais écrite à la main.

gamAa/
├── index.html              // accueil + grille des jeux
├── apropos.html
├── contribuer.html
├── documentation.html
├── roadmap.html
├── communaute.html
├── assets/
│   ├── logo.png
│   ├── icon.png            // favicon + icône des jeux
│   ├── site.css             // design système commun (header, boutons, cards)
│   ├── header.js             // composant d'en-tête, une seule copie pour tout le site
│   └── games.js               // registre des jeux, généré — ne pas éditer à la main
├── scripts/
│   └── build-games.js         // lit games/ et régénère assets/games.js
├── .github/workflows/
│   └── build-games.yml        // relance le script après chaque push sur main
└── games/
    ├── _template/             // modèle à dupliquer, ignoré par le script
    │   └── mon-jeu.html
    └── ton-nom/               // un dossier par développeur
        └── mon-jeu.html       // un fichier HTML autonome par jeu

Lancer le projet en local

Aucune installation nécessaire pour naviguer sur le site : clone le dépôt et ouvre index.html directement dans un navigateur, ou lance un petit serveur local pour naviguer confortablement entre les pages. Node.js n'est requis que pour régénérer assets/games.js après l'ajout d'un jeu (voir ci-dessous).

Ajouter un nouveau jeu

1. Duplique le dossier games/_template/ et renomme la copie avec ton nom : games/ton-nom/.

2. Renomme mon-jeu.html avec le nom de ton jeu, puis modifie le <title>, les balises <meta name="game:*"> et le code à l'intérieur. Ces informations sont ce que la liste des jeux affiche sur l'accueil.

3. Lance node scripts/build-games.js pour régénérer assets/games.js et voir ton jeu apparaître sur l'accueil et sur la page Communauté. Si tu oublies cette étape, la CI GitHub Actions s'en charge automatiquement une fois ta pull request mergée sur main. Le dossier games/_template/ lui-même est toujours ignoré par le script (tout dossier commençant par _ l'est).

Le composant d'en-tête

Toutes les pages du site (hors jeux) affichent le même en-tête via un seul composant partagé : assets/header.js. Chaque page pose juste un <div id="site-header"></div> suivi du script, et le lien actif du menu est détecté automatiquement d'après l'URL. Le style commun (en-tête, boutons, cartes) vient de assets/site.css, chargé sur chaque page. Pour créer une nouvelle page de site, copie ce bloc et n'ajoute que le CSS propre à ta page.

<link rel="icon" type="image/png" href="assets/icon.png" />
<link rel="stylesheet" href="assets/site.css" />
...
<div id="site-header"></div>
<script src="assets/header.js"></script>

Template de base pour un jeu

Ce squelette est exactement celui de games/_template/mon-jeu.html : duplique ce fichier plutôt que de recopier le code ci-dessous à la main. Un jeu reste un fichier HTML autonome (CSS et JS inclus) : il ne dépend pas du header du site. Les balises <title> et <meta name="game:*"> sont ce que scripts/build-games.js lit pour générer la fiche du jeu sur l'accueil : renseigne-les avec soin.

<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <link rel="icon" type="image/png" href="../../assets/icon.png" />
  <meta name="game:type" content="Arcade" />
  <meta name="game:description" content="Une phrase courte qui donne envie de jouer." />
  <meta name="game:dev" content="Ton Nom" />
  <meta name="game:date" content="JJ/MM/AAAA" />
  <title>Nom du jeu</title>
  <style>
    * { margin: 0; padding: 0; box-sizing: border-box; }
    body {
      font-family: "Segoe UI", Roboto, Arial, sans-serif;
      background: #1c2b39;
      color: #fff;
      min-height: 100vh;
      display: flex;
      flex-direction: column;
      align-items: center;
      justify-content: center;
    }
    /* ... styles du jeu ... */
  </style>
</head>
<body>
  <h1>Nom du jeu</h1>
  <div id="gameWrap"><!-- canvas ou DOM du jeu --></div>

  <script>
    // logique du jeu, tout en JavaScript natif
  </script>
</body>
</html>

Charte graphique

Navy — #1c2b39
Ambre — #f4b400

Typographie : police système (Segoe UI, Roboto, Arial, sans-serif), pas de police externe à charger.

Règle de simplicité visuelle : peu d'éléments à l'écran, priorité à la lisibilité et à la jouabilité immédiate. Pas d'emoji, design flat, sans ombres superflues.
